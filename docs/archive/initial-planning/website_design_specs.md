# Color Palette

- **Primary Color:** Pick a single bold hue for brand highlights (e.g. a trustworthy blue like **#2563EB**). Blue conveys _trust and stability_[\[1\]](https://elementor.com/blog/website-color-schemes-guide/#:~:text=Color%20Common%20Psychological%20Associations%20Common,Appetite%29%2C%20Travel). Use it for primary buttons, links, and key accents.
- **Secondary Color:** Choose a complementary highlight (e.g. **#F97316** orange). Orange brings _enthusiasm and friendliness_[\[2\]](https://elementor.com/blog/website-color-schemes-guide/#:~:text=Yellow%20Optimism%2C%20warmth%2C%20happiness%2C%20creativity%2C,Luxury%20Goods%2C%20Beauty%2C%20Wellness%2C%20Education). Use it sparingly for secondary buttons or section backgrounds to draw attention.
- **Accent Color:** Pick one distinct accent (e.g. **#7C3AED** purple). Purple evokes _creativity and expertise_[\[3\]](https://elementor.com/blog/website-color-schemes-guide/#:~:text=Orange%20Friendliness%2C%20enthusiasm%2C%20confidence%2C%20fun%2C,care%20Beauty%2C%20%E2%80%9CFor%20Her%E2%80%9D%20products). Reserve it for small highlights (icons, link hovers, or WebGL overlays).
- **Neutrals:** Define light and dark neutrals. For example, a very light gray or off-white **#F9FAFB** for backgrounds and a dark gray **#1F2937** for primary text. These ensure readability (dark text on light background) and give colors room to "breathe."
- **Contrast & Accessibility:** Ensure text/background pairs meet WCAG contrast (at least 4.5:1 for body text)[\[4\]](https://www.weaccess.ai/blogs/color-contrast-for-accessibility#:~:text=For%20example%2C%20AA%20requires%20a,a%20color%20to%20convey%20information). For example, dark gray (#1F2937) on #F9FAFB has very high contrast. Avoid low-contrast pairs (e.g. don't use orange text on white, since #F97316 on #FFFFFF is only ~2.8:1). Use a checker (WebAIM or the cited contrast guidance[\[4\]](https://www.weaccess.ai/blogs/color-contrast-for-accessibility#:~:text=For%20example%2C%20AA%20requires%20a,a%20color%20to%20convey%20information)) to verify all combinations (especially text and CTA buttons) pass AA or better.
- **Color Usage Rules:** Apply the **60-30-10 rule**: ~60% primary, 30% secondary, 10% accent[\[5\]](https://elementor.com/blog/website-color-schemes-guide/#:~:text=create%20a%20balanced%2C%20hierarchical%20design,of%20usability%20and%20legal%20compliance). In practice, use the primary color on major elements (headers, major buttons), the secondary on accent panels or secondary buttons, and the accent sparingly (small icons, button hovers). Limit the palette to ~3-4 colors total[\[6\]](https://www.webportfolios.dev/blog/best-color-palettes-for-developer-portfolio#:~:text=1). For example, use the primary blue as the dominant hue, orange as a secondary highlight, and purple only for focal elements (e.g. link underlines or WebGL highlights).
- **Dark Mode Compatibility:** Plan an alternate scheme with inverted neutrals (e.g. dark background ~#111827, light text ~#E5E7EB). Retain the same primary/secondary hues but adjust their brightness if needed. Ensure all UI elements invert correctly if a dark theme is toggled[\[7\]](https://drive.google.com/file/d/1ScaeA4eXaKkZQq48R8kz8SEr3zcMPLq0). (Dark mode is optional but appreciated by dev audiences[\[7\]](https://drive.google.com/file/d/1ScaeA4eXaKkZQq48R8kz8SEr3zcMPLq0).)

# Typography System

- **Primary Font:** Use a modern, highly legible sans-serif (e.g. **Inter** or **Roboto** from Google Fonts) with a web-safe fallback. Apply this to body text and headings. Sans-serifs look clean and technical, fitting a developer portfolio.
- **Secondary Font:** Optionally pair a serif or contrasting sans for headings or highlights. For example, use **Merriweather** or **Playfair Display** for headings. Combining serif+sans can add interest while maintaining harmony[\[8\]](https://www.leadpages.com/blog/best-google-fonts?srsltid=AfmBOoqDIuxipD2GFYECIbOE7p0ueJ8xI8dO_ehjltWkLZL8Dm23_Wsx#:~:text=,good%20choice%20for%20smaller%20text). The secondary font should complement the primary without clashing. (If used, deploy it sparingly - e.g. heading only.)
- **Monospace for Code:** Use a clear monospace like **Fira Code** or **Source Code Pro** for code snippets. This ensures code blocks are distinct. In Tailwind, set font-mono for code elements.
- **Hierarchy & Sizes:** Define a clear scale. Example (using Tailwind classes):
- **H1:** e.g. text-4xl (36px) bold - page/section titles.
- **H2:** text-3xl (30px) - subsection headings.
- **H3:** text-2xl (24px) - smaller headings.
- **Body:** text-base (16px) - default paragraph.
- **Labels/Small:** text-sm (14px) for captions or meta.
- **Code/Text:** font-mono text-sm for code blocks (monospace at readable size).
    Keep line-height comfortable (e.g. leading-7 for body) for readability. These pair well with Tailwind's utility classes.
- **Font Usage Rules:** Limit to 2-3 typefaces total to keep the site cohesive. Use the primary font for most text. Reserve the secondary font only for prominent elements (large headings) if at all. According to typography best practices, _"combine a serif with a sans-serif font"_ only if needed[\[8\]](https://www.leadpages.com/blog/best-google-fonts?srsltid=AfmBOoqDIuxipD2GFYECIbOE7p0ueJ8xI8dO_ehjltWkLZL8Dm23_Wsx#:~:text=,good%20choice%20for%20smaller%20text); otherwise stick with one family (e.g. Inter in multiple weights). Always include a standard fallback stack (e.g. font-family: 'Inter', sans-serif). Ensure headings are bold or heavier weight to stand out, while body text uses a regular weight.

# Design Style Guide

- **Layout & Spacing:** Use a consistent grid (e.g. multiples of 4px or 8px). Provide **generous whitespace** around sections and between elements. According to UI design principles, _"generous whitespace can make even messy interfaces look inviting and simple"_[\[9\]](https://www.learnui.design/blog/7-rules-for-creating-gorgeous-ui-part-1.html#:~:text=Good%2C%20generous%20whitespace%20can%20make,and%20simple%20%E2%80%94%20like%20forums). In practice, double typical default gaps (e.g. if default is 4px, use 8px-16px margins/padding). This "breathing room" ensures clarity. Employ ample vertical padding on containers and sections. Maintain at least 1.5× line-height on text.
- **Whitespace:** Don't crowd elements. As one guide notes, _"put space between your lines…elements…groups of elements"_[\[9\]](https://www.learnui.design/blog/7-rules-for-creating-gorgeous-ui-part-1.html#:~:text=Good%2C%20generous%20whitespace%20can%20make,and%20simple%20%E2%80%94%20like%20forums). Larger spacing around headers, paragraphs, cards, and buttons helps a modern, uncluttered look. Follow a consistent spacing scale (e.g. Tailwind's 4, 8, 12, 16, 24, 32).
- **Visual Style (Shadows vs. Flat):** Favor a mostly **flat design** with very subtle shadows ("flatty" design). Minimal shadows under cards or raised buttons add depth. For example, use a small drop-shadow on cards or active buttons to indicate elevation. This aligns with modern UI trends: flat elements with just a "dusting" of shadow cues[\[10\]](https://www.learnui.design/blog/7-rules-for-creating-gorgeous-ui-part-1.html#:~:text=However%2C%20giving%20up%20all%20lighting,and%20ability%20to%20convey%20information). (Avoid heavy skeuomorphic shadows; keep them light.) This approach is similar to Material Design's style of using only slight shadows to separate layers[\[10\]](https://www.learnui.design/blog/7-rules-for-creating-gorgeous-ui-part-1.html#:~:text=However%2C%20giving%20up%20all%20lighting,and%20ability%20to%20convey%20information).
- **Cards & Containers:** When displaying content (portfolio items, testimonials), use clean "cards" or panels with a background (white/neutral) and slight corner rounding (~4px). Distinguish sections with alternating background shades (white vs. very light gray) for contrast. Use consistent max-widths and centering (e.g. max-w-screen-lg mx-auto).
- **Buttons & Links:** Style buttons to clearly indicate clickability. Use the primary color for main CTA buttons (solid fill with primary background, white text), and secondary color or outline style for secondary actions. For example, a blue primary button on neutral background. On hover/focus, buttons can slightly darken or get a subtle lift (shadow) - keep it smooth. All clickable text links should use the primary or accent color and underline on hover. Maintain consistent button padding and rounded corners. Ensure button text meets contrast.
- **Icons:** Use a consistent icon set (e.g. **Lucide** line icons, as recommended in the tech stack). Keep icon stroke weight uniform. Icons may be colored with the primary or accent color where appropriate, or neutral for subtlety. Align icons with text (same baseline or center with text) to keep layout tidy.
- **Shadows & Surfaces:** If you use shadows, apply them consistently (e.g. shadow-md for cards, shadow-sm for small popups). Lightest surfaces (e.g. modal, dropdown) should be slightly elevated above page. Use white or very light backgrounds for cards, with slightly darker text for emphasis.
- **Motion & Micro-Interactions:** Make animations subtle and purposeful. For example, hover effects (button color shift, slight scale) and gentle transitions (150-300ms ease) give feedback. Avoid flashy or fast animations that could distract users. As accessibility guidance notes, _"avoid aggressive animations"_ and respect the user's prefers-reduced-motion setting[\[11\]](https://blog.logrocket.com/ux-design/accessible-hero-section-design/#:~:text=,use%20fast%20motions%20with%20animations). In practice: use fade/slide effects (easy-in-out), and do not auto-play large animations. Micro-interactions (like a focus ring, button ripple, or menu slide-out) should be smooth and not overly dramatic.
- **Navigation:** Keep the site nav clear and simple (e.g. horizontal menu or burger for mobile). Highlight the current section in the nav (e.g. bold or underline). Links should change style on hover. Maintain ample padding around nav items for touch targets.

# WebGL Integration Guidelines

- **Use Cases:** Integrate WebGL (3D/interactive) elements only where they enhance the experience - for example, in a **hero banner** or as visual accents in the background. A subtle interactive 3D scene (particles, rotating logo, data visualization) can impress, but keep it contained (e.g. full-browser hero or a section background). Always ensure that critical information (headings, CTAs) remains readable on top of any WebGL scene. For instance, if placing text over a 3D animation, overlay a semi-transparent color or gradient (using your brand neutrals) to preserve contrast[\[12\]](https://blog.logrocket.com/ux-design/accessible-hero-section-design/#:~:text=,use%20fast%20motions%20with%20animations).
- **Visual Harmony:** Match the WebGL look to the brand palette. You might tint lighting or fog in the 3D scene with the primary or accent color so it feels integrated (e.g. a blue glow around an object). Avoid clashing colors; keep the 3D style (e.g. wireframe, solid shapes) consistent with the flat UI style. Use simpler, stylized graphics rather than photorealism for coherence with a clean UI.
- **Performance:** Optimize all WebGL content. Use low-polygon models or optimized textures. Enable only when in view (use lazy loading or "render on scroll"). Limit 3D canvas resolution on small screens. Don't run full-scene animations at all times - if heavy, consider pausing or reducing on slower devices. Offer a static fallback or pause button. According to best practices, keep large animations lightweight so they don't slow page load[\[11\]](https://blog.logrocket.com/ux-design/accessible-hero-section-design/#:~:text=,use%20fast%20motions%20with%20animations).
- **When to Avoid WebGL:** If it does not add meaningful value, skip it. Do not use WebGL on pages where it distracts from content (e.g. the contact form page). Avoid heavy WebGL on mobile or on pages visited by low-bandwidth users. Always test on multiple devices: if a scene causes jank or blocks the initial render, it's safer to remove or simplify it. In short, use WebGL sparingly for _accent_, not as a requirement to access information.
- **Accessibility:** Provide controls or alternatives. For example, allow users to pause or disable an animation if needed. Respect prefers-reduced-motion by not auto-playing prolonged camera movements. Keep key text (like headings) outside of the WebGL canvas. Ensure any interactive 3D elements don't interfere with navigation or form inputs.

# Tone of Voice & Microcopy

- **Overall Tone:** First-person, confident, and professional yet approachable. Since this is a personal brand, use "I" (not "we"). For example, write "I create scalable, user-friendly websites…" rather than "Our team builds…". Keep language clear and direct. Use active voice and concise sentences[\[13\]](https://www.litmus.com/blog/email-accessibility-5-tips-for-writing-email-copy-for-everyone#:~:text=,email%20against%20accessibility%20best%20practices). (Accessible writing advises short, straightforward copy[\[13\]](https://www.litmus.com/blog/email-accessibility-5-tips-for-writing-email-copy-for-everyone#:~:text=,email%20against%20accessibility%20best%20practices).) Avoid jargon overload: mention technical terms like "Laravel" or "React" _sparingly_, always paired with the benefit to the client[\[14\]](https://drive.google.com/file/d/1i_RsejGREhbT8RIGJVE9J9K7b67BQYvE). For instance: _"I build interactive Laravel apps so your site is fast and secure."_
- **Homepage Headlines:** Use a bold tagline. E.g.: **"Freelance Web Developer & Real-Time 3D Specialist"**. Or a benefit-focused line like: _"Custom Web Development - Scalable, Secure, Tailored to You"_[\[15\]](https://drive.google.com/file/d/1dvVSRnZWQbGij_fxetqEBYe4vyVXpUjM)[\[14\]](https://drive.google.com/file/d/1i_RsejGREhbT8RIGJVE9J9K7b67BQYvE). This immediately tells visitors who you are and what you do. Under the main heading, a short subheading can combine both services: _"I help businesses grow online and create immersive 3D experiences."_ (Emphasize value, not just features.)
- **Services Page:** Write in a "business-friendly" tone focusing on outcomes[\[14\]](https://drive.google.com/file/d/1i_RsejGREhbT8RIGJVE9J9K7b67BQYvE). For example: _"I create websites that are not only visually appealing but also scalable and secure, ensuring your online presence grows with your business"_[\[14\]](https://drive.google.com/file/d/1i_RsejGREhbT8RIGJVE9J9K7b67BQYvE). Use bullet points for clarity (as seen in the content plan), and label sections simply (e.g. "Web Development", "3D & VR"). Each section should start with what you _deliver_ ("I develop X so you get Y"). Maintain a consistent tense (present simple) and voice.
- **CTAs and Buttons:** Use encouraging, action-oriented text. Examples: _"Let's Talk"_, _"Contact Me to Discuss"_, _"Get in Touch"_. The content plan suggests lines like _"Have a web project in mind? Let's talk."_ and _"Interested in AR/VR or 3D development? Contact me to discuss."_[\[16\]\[17\]](https://drive.google.com/file/d/1i_RsejGREhbT8RIGJVE9J9K7b67BQYvE). These are friendly yet direct. Don't bury the ask - every section ends with a clear next step (e.g. a button to contact).
- **Microcopy Style:** Keep paragraphs short (1-2 sentences each). Use simple, plain language to accommodate all readers[\[13\]](https://www.litmus.com/blog/email-accessibility-5-tips-for-writing-email-copy-for-everyone#:~:text=,email%20against%20accessibility%20best%20practices). Avoid fluffy marketing buzzwords. Instead of "state-of-the-art" or "cutting edge", say _"modern" or "the latest"_ if needed. Write as if speaking to one person: warm but not overly casual. For navigation labels (e.g. Home, About, Services), use clear nouns ("About Me" not "Who We Are"). Alt text and form labels should be straightforward ("Open Position for Laravel Developer").
- **Consistency:** Maintain the same tone across pages and languages. The user's company notes the French site is primary, but content should be consistent in style (formal yet friendly) in every language[\[18\]](https://drive.google.com/file/d/1i_RsejGREhbT8RIGJVE9J9K7b67BQYvE). For English CTAs, e.g. "Let's talk!", mirror a similarly warm invitation in French/Dutch. (Use native phrasing to keep it natural.)
