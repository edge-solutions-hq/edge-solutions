# Domain Docs

How the engineering skills should consume this repo's domain documentation when exploring the codebase.

## Layout

This repo uses a single-context layout.

## Before Exploring

- Read `AGENTS.md` for current repo guidance.
- Read `docs/README.md` for the documentation map.
- Read the relevant active docs under `docs/`; start with `docs/positioning.md`, `docs/architecture.md`, `docs/design-baseline.md`, and `docs/tech-stack.md`.
- Treat `docs/archive/initial-planning/` as historical context only.
- If `CONTEXT.md`, `CONTEXT-MAP.md`, or `docs/adr/` are added later, read them before architecture, diagnosis, TDD, PRD, or issue work.

## Domain Language

Treat Edge Solutions as AI-first, with web, integration, and realtime work as supporting execution depth rather than equal top-level offers.

## ADR Conflicts

If output contradicts a future ADR, surface it explicitly and either justify reopening it or mark the relevant work blocked.
